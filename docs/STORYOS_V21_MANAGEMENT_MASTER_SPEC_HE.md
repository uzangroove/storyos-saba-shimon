---

## 1. מטרת המערכת

StoryOS התחילה כמערכת הפעלה ותוכן לפעילויות של סבא שמעון, וכעת מתרחבת למערכת תפעולית מלאה לניהול העסק: גנים ומסגרות, אנשי קשר, פעילויות, התקשרויות, לוחות שנתיים, מפעילים, נוכחות, דוחות, כספים ומדיה.

המטרה היא שמערכת אחת תחבר בין שלושה עולמות:

1. **תוכן והפעלה** — ספרים, מצגות, סיפורים, תיאטרון בובות, יצירה, וידאו ומדיה.
2. **ניהול עסקי** — לקוחות, CRM, חוזים, מחירים, תשלומים, מסמכים ומעקב.
3. **תפעול בשטח** — לוח עבודה, מפעילים, כניסה/יציאה, דיווח פעילות והמשך טיפול.

המערכת מיועדת לגדול מסבא שמעון כמפעיל מרכזי למערך של מספר מפעילים, בלי צורך להחליף ארכיטקטורה כאשר העסק גדל.

---

## 2. עקרונות ארכיטקטורה

- ממשק Web רספונסיבי, מותאם מחשב וטלפון.
- Next.js כיישום הראשי.
- PostgreSQL / Supabase כמסד הנתונים המרכזי.
- Supabase Auth לזיהוי משתמשים.
- Row Level Security להגבלת מידע לפי תפקיד.
- Netlify מיועד לאירוח ממשק ה-Web.
- מדיה כבדה לא תישמר בתוך מסד הנתונים עצמו; במסד נשמור Metadata וקישורים.
- וידאו ציבורי/שיווקי יכול להישמר ב-YouTube; חומר פרטי ידרוש אחסון מתאים והרשאות.
- GitHub הוא מקור הקוד והיסטוריית הגרסאות.
- המערכת בנויה כך שבעתיד ניתן יהיה להוסיף PWA/אפליקציית מפעיל בלי לשנות את מודל הנתונים.

## 3. סוגי המשתמשים

### ADMIN

מנהל המערכת. גישה לכל המסגרות, אנשי הקשר, הפעילויות, ההתקשרויות, לוחות השנה, המפעילים, הדוחות, הכספים והגדרות המערכת.

### OPERATOR

מפעיל בשטח. רואה רק את השיבוצים שלו ואת המידע הדרוש לביצוע הפעילות. יכול לדווח כניסה, יציאה ודוח פעילות. אינו אמור לראות מידע כספי או נתונים של מפעילים אחרים.

בעתיד ניתן להוסיף תפקידים כגון OFFICE, SALES, ACCOUNTING או VIEWER.

## 6. מאגר כרמיאל

נבנה Seed של **95 מסגרות** מתוך מסמך המקור שהועלה לפרויקט.

המידע כולל, לפי הזמינות במקור: שם, סוג, גילאים, כתובת, שכונה, בעלות, טלפון, מקור אימות וקואורדינטות.

## 11. שנת לימודים ולוח חופשות

טווח העבודה המרכזי כרגע הוא ספטמבר 2026 עד יוני 2027 — תשפ״ז.

המערכת מנהלת Calendar נפרד לחופשות. מנוע התזמון מקבל:

`Schedule + Holiday Calendar → Sessions`

עקרון חשוב: מפגש שנופל בחופשה אינו נמחק. הוא נשמר כ-HOLIDAY לצורך היסטוריה, בקרה וחישובים.

תאריכי חופשות יוזנו רק לאחר אימות מול מקור רשמי מתאים לגני ילדים; אין להמציא מועדי חופשות.

---

## 12. מנוע התזמון

נבנה `generateSessions` שמקבל:

- יום בשבוע.
- שעת התחלה.
- שעת סיום.
- תאריך התחלה.
- תאריך סיום.
- טווחי חופשות.

ומחזיר את כל מועדי הפעילות.

סטטוסים ראשוניים:

- PLANNED — מפגש מתוכנן.
- HOLIDAY — מועד שנפל בחופשה.

מפגשים רגילים מקבלים Sequence Number. חופשה אינה מקבלת מספר מפגש רגיל.

---

## 13. שמירת מפגשים ב-Supabase

נבנה Endpoint מסוג Persist Sessions.

הזרימה:

`Contract → Schedule → Holidays → Generator → Sessions → Supabase`

השמירה נעשית ב-Upsert לפי Schedule + Date כדי למנוע כפילויות כאשר הלוח מחושב מחדש.

רק ADMIN רשאי ליצור/לעדכן את הלוח השנתי.

## 20. Login והרשאות

נוצר מסך `/login`.

התחברות מתבצעת מול Supabase Auth. לאחר ההתחברות נבדק התפקיד:

- ADMIN → `/management`
- OPERATOR → `/operator`

Access/Refresh Tokens מיועדים להישמר ב-HttpOnly Cookies.

נבנה מודל `app_users` המחבר בין משתמש Auth לבין תפקיד StoryOS.

## 28. זרימת העבודה הרצויה מקצה לקצה

### מנהל

`גן חדש/מיובא → השלמת איש קשר → שינוי CRM → יצירת התקשרות → בחירת פעילות ומחיר → Schedule → חופשות → יצירת מפגשים → שיבוץ מפעיל`

### מפעיל

`Login → הפעילות הבאה שלי → ניווט → כניסה → ביצוע StoryOS → יציאה → דוח פעילות → המפגש הבא`

### ניהול

`Sessions + Attendance + Reports + Contracts + Payments → Dashboard / בקרה / כספים / היסטוריה`

## 29. כיוון עתידי

הארכיטקטורה צריכה לאפשר בהמשך:

- מספר ערים ולא רק כרמיאל.
- מספר מפעילים במקביל.
- מספר פעילויות באותו גן.
- גנים + בתי ספר א׳–ג׳.
- CRM מכירות מלא.
- הצעות מחיר וחוזים.
- חשבוניות/קבלות דרך מערכת חיצונית.
- הודעות WhatsApp/Email ותזכורות.
- מפה חכמה ומסלולי נסיעה למפעילים.
- PWA/אפליקציה להתקנה בטלפון.
- Offline mode בסיסי לדיווח בשטח.
- Dashboard KPI.
- ניתוח רווחיות.
- ניהול ציוד ואביזרי פעילות.
- ניהול מלאי חומרי יצירה.
- פורטל לגן/גננת בעתיד, אם יהיה צורך.
- AI לסיכום דוחות, המלצת פעילות הבאה וחיפוש במאגר התוכן.
